# Работа 9. Протокол DHCP

## Назначение

DHCP избавляет администратора от ручной настройки параметров каждого узла. Клиент может получить адрес IPv4, маску, шлюз и DNS-настройки от сервера, что упрощает подключение устройств и снижает вероятность случайного повторного назначения адреса.

## От ранних механизмов к DHCP

До DHCP существовали RARP и BOOTP. В случае RARP сервер сопоставлял MAC-адрес клиента с IP-адресом, но не передавал весь набор сетевых параметров. BOOTP добавил передачу сведений для загрузки бездисковых систем и пересылку запросов между сетями. DHCP развил BOOTP и поддерживает выдачу адреса на ограниченное время.

## Способы распределения адресов

- При ручной привязке администратор заранее связывает MAC-адрес устройства с конкретным IP.
- При автоматической выдаче адрес из пула закрепляется за клиентом постоянно.
- При динамической аренде клиент получает адрес на заданный срок; после освобождения его можно выдать другому устройству.

Динамический пул удобен, когда не все пользователи одновременно присутствуют в сети. Например, для пятидесяти одновременных подключений необязательно резервировать адрес для каждого из пятисот сотрудников.

## Получение аренды

Обычная последовательность обмена называется DORA:

1. **Discover** — клиент рассылает запрос, чтобы найти DHCP-сервер.
2. **Offer** — сервер предлагает свободный адрес и конфигурацию.
3. **Request** — клиент запрашивает выбранное предложение.
4. **ACK** — сервер подтверждает аренду.

Если DHCP-сервер находится за пределами локального сегмента, запрос может передать DHCP relay. До истечения аренды клиент пытается ее продлить. Если это не удается и срок заканчивается, прежний адрес больше нельзя использовать.

## Ограничения

Часто меняющийся IP усложняет доступ к устройству по постоянному имени и применение правил, завязанных на адрес. Поэтому серверы и инфраструктурное оборудование обычно получают статическую адресацию либо резервирование, а DNS обновляют согласованно с DHCP.
